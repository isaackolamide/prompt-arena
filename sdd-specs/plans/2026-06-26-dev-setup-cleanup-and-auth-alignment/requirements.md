# Feature Requirements: dev-setup-cleanup-and-auth-alignment

## Scope

In scope:
- Disabling the `realtime`, `storage` (and its sub-properties), and `edge_runtime` services in `supabase/config.toml`.
- Deprecating and removing `/api/auth/register` and `/api/auth/login` endpoints from the FastAPI backend.
- Removing all password fields, forms, and states from `frontend/src/App.tsx`.
- Implementing a Magic Link and OTP verification view (with inputs for email and verification token) in `frontend/src/App.tsx`.
- Designing a dark-mode glassmorphic user interface in `frontend/src/App.tsx` with curated CSS styles, glowing border details, responsive panels, and hover animations.
- Setting up Playwright E2E tests to cover the complete Magic Link request and OTP input authentication flow.

Out of scope:
- Executing user submissions via AWS Lambda / Firecracker sandboxing.
- Implementing game countdown timers, game sessions, or scoring logic.
- Building the public scoreboard or scorecard viewer dashboard.

## Decisions

Key technical decisions made:
- **Optimization Strategy**: Keep Postgres (`db`), PostgREST (`api`), GoTrue (`auth`), Inbucket (`local_smtp`), and the Studio dashboard (`studio`) enabled. This drops the Docker local container footprint by 4 containers, significantly reducing CPU/RAM usage.
- **Invite-only Flow**: Reject password login. The player flow is strictly: Email submission -> Magic Link OTP sent -> Enter OTP -> Access dashboard.
- **Visual Design Rules**: Avoid standard browser elements and solid layouts. Use custom backdrop filters, semi-transparent backgrounds, sleek typography (Outfit/Inter), and state transition indicators.

## Context

Why this feature is being built:
- Local development machine performance is degraded by unused docker containers (Realtime, Storage, Imgproxy, Edge Functions runtime) running in the background.
- The existing authentication UI forces email/password registration and login, which contradicts the core project mission of whitelisted, invite-only players authenticating strictly through Magic Links.
- The UI/UX is currently a basic form layout and needs a premium design to align with modern web app aesthetics.

## Security Constraints

- **Input Sanitization**: Email payloads submitted to endpoints must be strictly validated using Pydantic `EmailStr` rules in backend schemas.
- **PII Protection**: Plaintext emails must never be printed to stdout or written to logs. The existing `mask_email` helper function must be consistently applied to log messages.
- **Strict Typing**: The frontend React code must be fully type-safe. Escape routes such as `any` are forbidden.
- **Access Control**: Session tokens generated by OTP verification must be handled securely on the client via HTTP request headers.

## Telemetry & Observability

- **Auth Logs**: Log the generation and validation attempts of OTP tokens, reporting either success or failure status with masked email markers.
- **Error Handling**: Log detailed tracebacks for unexpected auth exceptions or Supabase GoTrue AuthApiErrors to ease local debugging.
- **Latency Monitoring**: Measure and trace processing times of Magic Link send and verification API calls.

## Migration & Deprecation Plan

- **Backend Route Deletion**: Completely remove the `/api/auth/register` and `/api/auth/login` functions from the FastAPI router.
- **Database Cleanup**: The database schema uses Supabase auth, which natively handles OTP. No structural schema migrations are necessary since the `auth.users` schema is fully managed.
- **Frontend Refactoring**: Cleanly delete `registerEmail`, `registerUsername`, `registerPassword`, `loginEmail`, and `loginPassword` variables and handlers from client state.
- **Test Archive**: Remove legacy unit tests that target password sign-ins.
